# Phase 6 task 2 — RULER NIAH 4k subset eval

**Date:** 2026-05-02
**Status:** Design approved; ready for implementation plan
**SPEC reference:** `docs/SPEC.md` §6 task 2 ("Wire `niah_single` + `niah_multikey` + `niah_multivalue` from `NVIDIA/RULER` against our patched model. Acceptance: ≥85% at retention=0.25 vs dense at 4k.")

## Problem

The Phase 5/6 passkey eval is methodologically broken:
- Llama-3.2-3B has no upstream DuoAttention pattern, so `head_pattern` was generated by un-seeded `torch.rand(...) < 0.7` — different across runs.
- `scripts/phase6_diag_passkey_3b.py` confirmed: with `seed=7` at ctx=4096, both Phase 5 and Phase 6 wiring produce **0/6 with bit-identical outputs**. Phase 5's recorded "6/6" was a lucky pattern.
- Passkey doesn't isolate sparse-attention quality from head-pattern variance.

We need a reproducible quality gate. SPEC commits to RULER NIAH (3 tasks) at ctx=4k, retention=0.25 vs dense, ≥85% pass.

## Decisions

| Question | Decision |
|---|---|
| Vendor RULER vs roll our own | **Hybrid (C)** — own generator harness, but prompt template + scoring rules vendored verbatim from `NVIDIA/RULER` as comment blocks. Numbers citable as "RULER NIAH protocol". |
| DuoAttention pattern problem | **All-retrieval (A)** — `head_pattern = ones`, every head runs Quest top-k at retention=0.25 + sinks + window. Eliminates head-pattern variance as a confound. The harder test (no streaming-head escape). DuoAttention training deferred to v2. |
| Dense baseline | **Vanilla SDPA (A)** — same model, `attn_implementation="sdpa"`, no flashquest patches. The SPEC gate is exactly "≥85% vs dense"; this is dense. |
| Sample count | **n=20/task default (C), n=64 for release (B)** — n=20 gives CI ~±10%, runs in ~2.5 hr per config. Adequate for go/no-go. `--n-samples` CLI arg lets release tag use 64 (~24 hr per config). |

## Components

### `niah.py`

Three pure-function task generators following the `NVIDIA/RULER` protocol (see `vendor/RULER/scripts/data/synthetic/niah.py` for the published prompt templates).

```python
def make_prompt(
    task: str,                     # "single" | "multikey" | "multivalue"
    ctx_len: int,                  # target token length, e.g. 4096
    tokenizer,                     # transformers tokenizer for length budgeting
    seed: int,
) -> tuple[str, list[str]]:
    """Returns (prompt, expected_keys).

    - "single":     1 needle in essay filler. expected_keys = [needle_value].
    - "multikey":   1 needle + 3 distractor needles with different keys.
                    expected_keys = [target_value]. (target key matches the question.)
    - "multivalue": 1 key with 4 different values scattered through filler.
                    expected_keys = [v1, v2, v3, v4]. (must retrieve ALL.)
    """

def score(generated: str, expected_keys: list[str]) -> bool:
    """Per RULER: case-sensitive substring match; all expected_keys must appear in generated."""
```

Filler corpus: Paul Graham essays (standard for NIAH eval, ~200KB suffices for 4k context).

@torch.no_grad()
def run_niah(

### `phase6_run_ruler_4k.py`

CLI signature:
```bash
python scripts/phase6_run_ruler_4k.py \
  --model casperhansen/llama-3.2-3b-instruct-awq \
  --ctx-len 4096 \
  --n-samples 20 \
  --retention 0.25 \
  --num-sinks 4 \
  --window-pages 2 \
  --page-size 64 \
  --seed 0
```

Loads the model **twice**: once dense (no patch), once patched with `head_pattern=torch.ones(num_layers, num_kv_heads, dtype=bool)` (all-retrieval), retention=0.25. Runs all 3 tasks under both. Computes per-task ratio = patched_hits / dense_hits. Gate: ratio ≥ 0.85 for every task.

Output `benchmarks/phase6_ruler_4k.json`:
```json
{
  "model": "casperhansen/llama-3.2-3b-instruct-awq",
  "ctx_len": 4096,
  "n_samples": 20,
  "retention": 0.25,
  "tasks": {
    "niah_single":     {"dense_hits": 19, "patched_hits": 18, "total": 20, "ratio": 0.947, "pass": true},
    "niah_multikey":   {"dense_hits": 17, "patched_hits": 15, "total": 20, "ratio": 0.882, "pass": true},
    "niah_multivalue": {"dense_hits": 18, "patched_hits": 16, "total": 20, "ratio": 0.889, "pass": true}
  },
  "gate": "≥85% vs dense at retention=0.25 + all-retrieval head_pattern",

```

If `all_pass`, tag `phase-6-task-2`.

## Data flow

```
seed → make_prompt(task, ctx_len, tok, seed=i) → (prompt, keys)
prompt → tok → ids → model.generate(max_new_tokens=128) → text → score(text, keys) → bool
```

No streaming, no caching of generations across runs. Deterministic given (model, seed, task, ctx_len, n_samples).
